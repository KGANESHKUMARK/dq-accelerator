# Microsoft Fabric integration — SYNTHETIC sample

> **SYNTHETIC** — no real Fabric workspace, OneLake, or credentials were used.
> These files show the *pattern* a Fabric PySpark notebook follows before and
> after DQ Accelerator integration. Verified locally against the file-based
> harness, not a live Fabric environment.

| File | Purpose |
|---|---|
| `orders_pipeline_original.py` | Typical Fabric lakehouse notebook: raw files → `bronze_orders` → `silver_orders` Delta tables |
| `orders_pipeline_dq_integrated.py` | Same notebook with the engine inserted inline (`«DQ INTEGRATION»` markers) — ~12 lines added, zero transforms changed |

Pairing assets in this repo:

- Manifest: `config/pipelines/FABRIC_ORDERS_PIPELINE.yaml` (platform `FABRIC`)
- Sample data: `sample_data/bronze/orders.csv`
- Ruleset: `config/rulesets/orders_v1.yaml` (generated by `dqctl bootstrap`)

On a real Fabric workspace: upload the `dq_core` wheel via Environment →
Public libraries, put the config bundle under Lakehouse `Files/`, and the
integrated notebook runs unchanged.

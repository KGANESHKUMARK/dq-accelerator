Build a working, demonstrable initial Proof of Concept for an Enterprise Data Quality Accelerator.
The POC must demonstrate:
A reusable Apache Spark Data Quality Core Engine.
Onboarding of existing Databricks PySpark pipelines.

Use safe, controlled rule execution. Never execute unrestricted eval() or generated code.
5.6 Deterministic remediation

- UPPERCASE.

Do not invent critical customer or banking information.

5.8 Confidence policy engine
Default confidence threshold: 90%.
Configurable as a decimal between 0 and 1.
Test:
- 89%.
- 89.99%.
- 90%.
- 95%.
- 100%.
Policy:
Below threshold:
- Quarantine.
At or above threshold:
- Eligible for automatic correction when the remediation policy allows it.
Sensitive columns:
- Customer identity.
- Account identifiers.
- Transaction amounts.
- Regulatory information.
Require human approval for high-impact corrections unless an approved deterministic reference-based policy explicitly permits them.
A high AI confidence alone is not proof of correctness.
5.9 Quarantine and revalidation
Create a quarantine DataFrame containing:
- Original record.
- Record reference.
- Pipeline ID.
- Dataset ID.
- Run ID.
- Failed rule IDs.
- Failure reasons.
- Proposed correction.
- Confidence.
- Remediation status.
Corrected records must be revalidated.
A correction that fails post-validation must also be quarantined.
Provide:
- accepted_dataframe.
- quarantine_dataframe.
- validation_results.
- remediation_results.
- execution_metrics.

Example:
from dq_core import DataQualityEngine
from dq_core.context import PipelineContext
Existing Databricks Spark session
Existing DataFrame from the user's pipeline
engine = DataQualityEngine.from_config(
"config/engine.yaml"
)
context = PipelineContext(
pipeline_id="DATABRICKS_CUSTOMER_PIPELINE",
pipeline_run_id="DEMO_RUN_001",
platform="DATABRICKS",
runtime="PYSPARK",
dataset="customers",
stage="SILVER",
ruleset_version="1.0"
)

dataframe=customers_df,
ruleset="config/rulesets/customers_v1.yaml",
policy="config/policies/default.yaml",
context=context
)

quarantine_df = result.quarantine_dataframe
Continue the existing pipeline using accepted_df.

10. BRONZE / SILVER / GOLD DATA FLOW
BRONZE:
- Preserve original input.
- Read the existing dataset.
- Capture metadata.
- Profile dataset.
- Generate candidate rules.
SILVER:
- Load approved rules.
- Run validation.
- Apply deterministic fixes.
- Evaluate AI proposals.
- Apply eligible corrections.
- Revalidate.
- Separate accepted records from quarantine.
GOLD:
- Validate business constraints.
- Check transaction-to-customer relationships.
- Execute configured business-level checks.
- Publish only data that passes the Gold quality policy.
Use local POC paths:
data/bronze/
data/silver/
data/gold/
data/quarantine/
For Databricks integration, use configurable output paths. Do not assume local filesystem paths inside a Databricks cluster.
